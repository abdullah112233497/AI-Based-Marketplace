## 1. Executive Summary & Architecture Overview

Phase 3 transitions the AI-Powered Multi-Vendor Technology Marketplace from foundational identity and authentication (Phase 1 & 2) into a fully functional product catalog, multi-vendor agent listing management portal, high-performance search and facet engine, dynamic category specification system, and public storefront ecosystem.

All implementations strictly adhere to production-grade architectural standards:
- **FastAPI Async Engine**: Fully asynchronous request processing using `asyncpg` with zero blocking I/O calls.
- **Neon Serverless PostgreSQL with JSONB GIN Indexing**: Dynamic category specifications modeled inside PostgreSQL `JSONB` columns indexed with generalized inverted indexes (`GIN`) for sub-millisecond facet querying across arbitrary technical specs.
- **Strict Multi-Tenant Security**: Guaranteed server-side ownership enforcement on all product mutations (`agent_id == current_user.agent.id`), completely preventing cross-tenant modifications or unauthorized inventory adjustments.
- **Dynamic Spec Validation Engine**: Category-level schema validation ensuring options constraints and field definitions match category contracts.
- **Dual-Backend Intelligent Routing**: Frontend transparently directs catalog, product, category, and seller management traffic to FastAPI (`http://localhost:8000/api/v1`) while preserving Express prototype routes on port 5000 for upcoming transactional phases.
- **Strict Non-Fractional PKR Currency Standard**: All prices and compare-at rates stored and computed as integer Pakistani Rupees (PKR), preventing floating-point rounding errors.

### 4.2 Validation Execution (`app/services/spec_validator.py`)
Before any product creation or dynamic update is saved:
1. The engine checks provided values against the defined option list (case-insensitively).
2. If an invalid option is provided, an `AppException(status_code=422, code="INVALID_SPECS")` is raised with the allowed option list.
3. If `enforce_required=True` is requested, missing mandatory specifications raise 422.
4. Non-conflicting custom specifications are preserved.

## 5. Multi-Vendor Listing Architecture & Security Boundaries

### 5.1 Multi-Tenant Isolation
- In this marketplace, every seller is an `Agent` associated with a `User`.
- Product creation (`POST /api/v1/agent/products`) automatically binds the listing to `current_user.agent.id`.
- Product updates (`PUT` and `PATCH /api/v1/agent/products/{id}`) and deletion (`DELETE /api/v1/agent/products/{id}`) strictly verify:
  ```python
  if product.agent_id != agent.id:
      raise ForbiddenException("Access denied: You do not own this product listing", code="FORBIDDEN")
  ```
- Attempting to update another agent's product listing immediately halts execution with HTTP 403 `FORBIDDEN`.

### 5.2 Multi-Vendor Duplicate Listing Support
- Different agents can sell identical devices (e.g., multiple agents selling "Samsung Galaxy S24 Ultra 256GB").
- Product titles are not globally unique; uniqueness is enforced per slug by the utility `generate_unique_product_slug()`, which automatically appends collision counters (`samsung-galaxy-s24-ultra-2`, `-3`).

## 6. Public Catalog, Search, and Filtering Engine

### 6.1 Endpoint: `GET /api/v1/products`
Supports rich query params:
- `search`: Case-insensitive ILIKE matching on `title`, `description`, and `brand`.
- `category`: Matches category ID or slug (`mobiles`, `laptops`, `accessories`).
- `brand`: Filter by brand name.
- `condition`: Filter by `ProductCondition` (`NEW`, `USED`, `REFURBISHED`).
- `minPrice`, `maxPrice`: Filter by integer PKR range.
- `inStock`: Boolean flag ensuring `stock > 0`.
- `agentId`: Filter by merchant ID.
- **Dynamic Spec Extraction**: Any additional query parameter (e.g. `?ram_gb=12&storage_gb=512`) dynamically extracts and filters the JSONB spec attribute via:
  ```python
  func.jsonb_extract_path_text(Product.specs, key).ilike(val)
  ```
- `sort`: Supports `newest`, `price_asc`, `price_desc`, `rating`, `popular`.
- `page`, `limit`: Pagination parameters returning standard metadata (`page`, `limit`, `total`, `totalPages`).

### 6.2 Status & Agent Filtering Guard
The public catalog query strictly enforces that only listings where:
- `Product.status == ProductStatus.PUBLISHED`
- `Agent.status == AgentStatus.APPROVED`

Draft, unpublished, and archived listings—as well as listings belonging to suspended or pending agents—are excluded from public queries.

## 8. Public Agent Directory & Public Storefront

### 8.1 Directory: `GET /api/v1/agents/directory`
- Lists all active, approved vendors (`AgentStatus.APPROVED`).
- Supports filtering by `city` (e.g., "Lahore", "Karachi", "Islamabad") and keyword search.
- Returns seller rating, verification badges, contact details, and product counts.

### 8.2 Merchant Storefront: `GET /api/v1/agents/public/{slug}`
- Returns complete public merchant profile by `shop_slug` or UUID.
- Returns all published listings owned by that merchant with loaded category and brand metadata.
- Returns HTTP 404 `AGENT_NOT_FOUND` if the merchant does not exist or is not approved.

## 9. Seller Portal & Agent Listing Management

### 9.1 Overview: `GET /api/v1/agent/overview`
- Returns seller dashboard metrics: total products, total stock, and low-stock alert items (`stock < 5`).

### 9.2 Inventory List: `GET /api/v1/agent/products`
- Lists all listings belonging to the authenticated approved agent (excluding archived).

### 9.3 Partial Updates: `PATCH /api/v1/agent/products/{id}`
- Supports atomic partial updates via `ProductUpdatePartialRequest` for quick price adjustments, stock increments/decrements, and publish/unpublish toggles.

### 9.4 Soft Deletion: `DELETE /api/v1/agent/products/{id}`
- Safely sets `product.status = ProductStatus.ARCHIVED` and decrements `agent.product_count`.
- Archived items are immediately hidden from the public catalog.

## 10. Frontend Cutover Architecture (`apps/web/src/lib/api.ts`)

The Next.js 14 application uses intelligent URL dispatch in `resolveApiUrl()`:
```typescript
function resolveApiUrl(path: string): string {
  // Routes transitioned to FastAPI (port 8000)
  if (
    path.startsWith('/auth') ||
    path.startsWith('/admin') ||
    path.startsWith('/products') ||
    path.startsWith('/categories') ||
    path.startsWith('/agent') ||
    path.startsWith('/agents')
  ) {
    return `${FASTAPI_URL}/api/v1${path}`;
  }

  // Transactional routes remaining on Express mock until subsequent phases
  return `${EXPRESS_URL}/api${path}`;
}
```

This guarantees seamless end-to-end operation between the React Query frontend hooks and the FastAPI backend.
